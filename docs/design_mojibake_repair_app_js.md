# Part 1. 詳細設計書

## 1. 背景・目的（Why）

- 「日付なし」で Inbox へ移動する処理自体は正常。表示される**トースト文言がソース内で既に化けている**。
- 目的: 化けた日本語文字列・コメントを**元の正しい日本語に復旧**し、再発を防ぐ。
- 副次目的: テンプレートリテラルの `${...}` が壊れて変数展開されない不具合を直す。

## 2. 調査結果（事実）

### 2.1 混入コミットの特定（git で確認済み）

| コミット | 日付 | app.js の化け行数* | 備考 |
| :--- | :--- | :---: | :--- |
| `a6054c4` (v1.9.13) | 09-26 | **0** | **最後の正常版** |
| `4f34850` fix(banner): restore UTF-8 ... | 10-01 | 76 | **混入点**。app.js が 396 行変更 |
| `9ba0147` fix(habits): ... | 10-01 | 75 | 化けを引き継ぎ、その上に変更 |
| HEAD 以降 | - | 約 79+ | 現在の作業ツリー |

\* `縺|繧|譌` を含む行数の簡易カウント。実数は**スクリプトで全数列挙して確定する**（後述）。

皮肉にも混入点は「UTF-8 を復元する」ための修正コミットだった。

### 2.2 化けの性質

- **二重エンコード**: UTF-8 のバイト列を CP932(Shift_JIS) として解釈し、再度 UTF-8 で保存したもの。
  例: `日付なし` → `譌･莉倥↑縺・`
- 原因の推定: PowerShell の `Get-Content` / `Set-Content`（`-Encoding` 未指定）で app.js を書き換えた。Windows PowerShell 5.x の既定は CP932。**推定であり、ツール特定は不要**。
- **`${` の破壊**: `「${task.title}」` が `縲・{task.title}縲・` になる。
  - `「` は UTF-8 で `E3 80 8C`。CP932 では末尾の `8C` が 2 バイト文字の先頭になり、次の `$`(0x24) を巻き込んで消える。
  - 結果、`$` が失われ、`{task.title}` が文字列のまま表示される。スクリーンショットと一致。
- **一部は不可逆**: 上記の巻き込みや `・`（U+30FB）への置換が起きた箇所は、逆変換だけでは元に戻らない。

### 2.3 影響範囲

- **[app.js](file:///c:/Users/nonst/recover/obsidian%20folder/006_AI_Workspace/habit-app/app.js)**: コメント・UI 文言・ラベル・トースト・`deferTask` の `actionLabel`（2967/2980/2993/3009/3021 行ほか）。
- `style.css:564`、`js/views/tableView.js:657, 711, 2513`: ヒットあり。**混入原因が同じか未確認**（個別に判定）。
- `tests/test_banner_utf8_runner.js`: 化けパターンを検出対象として含むため、ヒットは**意図的な可能性が高い**（要確認、修正対象外）。
- 動作リスク: 化けた文字列が**比較キー**に使われていると、ロジックが壊れる。
  例: `statusLabels`（1768 行）、フィルタの既定値 `'縺吶∋縺ｦ'`（1770 行）。コメントだけの化けより危険度が高い。

> [!NOTE]
> 先の調査報告で「化けは部分的」と書いたのは誤り。全体調査の結果、**app.js 全域に及ぶ**と訂正する。

## 3. 設計方針（How）

### 3.1 方式の比較

| 案 | 内容 | 長所 | 短所 |
| :--- | :--- | :--- | :--- |
| **A（推奨）** | 正常版 `a6054c4` を基準に、化けた行を**元テキストで置換**。その後の機能変更(`4f34850`, `9ba0147` 等)は維持 | 不可逆箇所も確実に復旧。検証が容易 | 差分の突き合わせが必要 |
| B | 現行ファイルを逆変換（cp932 でエンコード → UTF-8 でデコード） | 手作業が少ない | `$` 消失・`・` 置換の箇所は復元不能。誤復元の恐れ |
| C | `a6054c4` へ丸ごとロールバック | 最も単純 | 10-01 以降の機能修正（バナー・習慣判定など）が消える |

**採用: 案A を軸に、案B を補助として併用する。**

1. 現行 app.js の「化け行」を全数抽出する。
2. 各行について、`a6054c4` に**同一行（または対応行）があるか**照合する。あれば元行を採用する。
3. 無い行（`4f34850`/`9ba0147` で追加・変更された行）は、案B の逆変換で復元を試みる。
4. 逆変換で復元できない行（`$` 消失、`・` 混入）は、**文脈から手動で復元**し、一覧表に記録する。
5. 案C は採用しない（機能修正の巻き戻しになるため）。

### 3.2 復元ルール

- **`${...}` の再挿入**: 化けた直後に `{xxx}` が残っている箇所は、`$` を補う。
  対象パターン: `縲・{` → `「${`、`縲阪ｒ` → `」を`。
- 復元後の文言は、同種の正常な文言（2704 行・3122 行など）に**表記を揃える**。
- 復元しきれない文言は、新規に作らず、**原文が不明であることを報告**して確認を取る。
- **ロジックには触れない**。文字列とコメントのみを変更する。

### 3.3 変更対象ファイル

| ファイル | 変更内容 |
| :--- | :--- |
| `app.js` | 化けた文字列・コメントの復旧（最大の対象） |
| `style.css` / `js/views/tableView.js` | 564 行 / 657, 711, 2513 行を確認し、化けなら復旧 |
| `sw.js` | `CACHE_NAME` を `gendrive-lite-v1919` から次の版へ更新（PWA が古い app.js を配り続けるのを防ぐ） |
| `tests/test_mojibake_guard.js` ＋ `.ps1` | 新規。再発防止テスト |
| `release_notes/` | 必要に応じてリリースノート（5 項目規格） |

### 3.4 再発防止策

1. **ガードテスト**: 全 `.js/.css/.html` に化けパターンが無いことを自動検査する。
   - 検出語: `縺|繧|譌|蜿|驕|螳|笞|邂|・{` など。
   - 除外: `test_banner_utf8_runner.js`（検出パターンとして意図的に保持）。
2. **`${` 破壊の検査**: ソース中の `{task.title}` のように `$` を伴わない `{識別子.識別子}` がテンプレート内にないかを検査する。
3. **編集ルール**: スクリプトでソースを書き換える場合は、**`[IO.File]::ReadAllText/WriteAllText` に `UTF8Encoding($false)` を明示**する。`Get-Content`/`Set-Content` の既定は使わない。
4. 同ルールを `AGENTS.md` へ追記するか、別途提案する（変更は許可を得てから）。

## 5. リスクと対策

| リスク | 対策 |
| :--- | :--- |
| 比較キーの化け文字列を直し、保存済みデータと不整合になる | 化けたキーで保存された localStorage データが無いか、`storageService.js` 等の参照を調べる。ある場合は**実装を止めて報告** |
