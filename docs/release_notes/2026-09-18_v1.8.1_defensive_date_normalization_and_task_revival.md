## 1. 🔍 事前コード分析・設計・リファクタリング分析

### 1-1. インシデント発生の背景と根本原因分析
v1.8.0において「天才アイデアの箱（11件）」のサルベージとディープマージ機構を配備した直後、哲生さんより以下の重大な事象が報告されました。
- 「天才アイデアの箱はリカバリされているが、デイリー画面に定期タスク（5件）しか出ず、本日（9/18）登録したはずの単発タスクが全く復活していない」
- 「カレンダーを見ても、日付の下にタスクの存在を示すドット（・）が一切表示されていない」
- 「明日以降約1ヶ月先まで毎日登録していた期日指定単発タスク（約26件）も画面に出てこない」

この緊急報告を受け、Google Driveバックアップ（`HABIT_EXPORT_20260918_0521`）、Google Apps Script（GAS）API、およびクライアント側描画パイプラインの深層コード解析を実施しました。その結果、**「データ自体はクラウドに存在しているにもかかわらず、クライアント側で100%除外されていた」**という致命的なシリアライズ不整合が判明しました。

#### 根本原因の構造的メカニズム
1. **Googleスプレッドシート起因の長文Date型シリアライズ問題**:
   Googleスプレッドシート上のタスクシートにおいて、予定日（`scheduledDate`）が日付形式セルとしてフォーマットされていたため、GAS API経由でJSON出力される際に `YYYY-MM-DD` ではなく、以下のようなJavaScriptの長文Date文字列として書き出されていました。
   ```text
   scheduledDate: "Fri Sep 18 2026 00:00:00 GMT+0900 (日本標準時)"
   scheduledDate: "Sat Sep 19 2026 00:00:00 GMT+0900 (日本標準時)"
   ```
2. **デイリー画面判定（`isTaskForSelectedDate`）における厳格一致（`===`）の罠**:
   `app.js` の `isTaskForSelectedDate(task, dateObj)` は、表示対象日の日付キー（`"2026-09-18"`）とタスクの `scheduledDate` を以下のように完全一致比較していました。
   ```javascript
   if (task.scheduledDate) {
     return task.scheduledDate === dateKey; // ← "Fri Sep 18 2026..." === "2026-09-18" は常に false!
   }
   ```
   このため、本日（9/18）に予定されていた単発タスク（J PREP Week1〜Week4、計画リスケ、ALL-IN、謝恩会返信など）が**すべてデイリー画面の抽出フィルタで弾かれ、定期タスクのみが表示される**状態に陥っていました（天才アイデアは `bucket === 'genius'` のみで判定される専用ビューのため正常に11件表示されていた）。
3. **カレンダー活動ドット判定（`hasActivityOnDate`）における厳格一致の罠**:
   `js/views/calendarView.js` の `hasActivityOnDate(dateKey)` も同様に `t.scheduledDate === dateKey` で厳密比較していたため、タスクが存在するにもかかわらずドット判定がすべて `false` となり、カレンダー上のドット（・）がすべて消滅していました。
4. **全ビュー・キャリーオーバー判定（`allView.js`）における日付比較不全**:
   `allView.js` のキャリーオーバー判定でも `t.scheduledDate < todayKeyStr` と単純文字列比較されていたため、長文Date文字列が期待通り評価されないリスクが存在しました。

### 1-2. 防衛的日付正規化（Defensive Date Normalization）アーキテクチャの設計
単にスプレッドシート側の文字列を `YYYY-MM-DD` に一括置換するだけでは、将来スマホアプリや外部インポート、別端末のブラウザから長文Date文字列が流入した際に再発します。
そこで、**「ポスレルの法則（堅牢性の原則：受信するデータは寛容に、送信するデータは厳格に）」**に基づき、システム全層に防衛的日付正規化エンジンを配備しました。

1. **多重フォーマット対応パーサー `normalizeToLocalDateKey(val)` の強化 (`js/utils/dateUtils.js`)**:
   - 標準 `YYYY-MM-DD` 形式は即座にパススルー。
   - スラッシュ形式（`YYYY/M/D`）を2桁ゼロ埋め `YYYY-MM-DD` へ即時変換。
   - `Fri Sep 18 2026 00:00:00 GMT+0900 (日本標準時)` 等の長文Date文字列を正規表現（`^[A-Za-z]{3}\s+([A-Za-z]{3})\s+(\d{1,2})\s+(\d{4})`）でミリ秒未満で高速パースし、JST基準の `2026-09-18` へダイレクト正規化。
   - DateオブジェクトやISO文字列もローカル時刻基準で安全に抽出。
   - null/undefined/空文字への防衛ガードを完備。
2. **全表示レイヤーでの正規化インターセプト**:
   - `app.js` (`isTaskForSelectedDate`): `normalizeToLocalDateKey(task.scheduledDate) === dateKey`
   - `calendarView.js` (`hasActivityOnDate`): `normalizeToLocalDateKey(t.scheduledDate) === dateKey`
   - `allView.js` (キャリーオーバー判定): `normSchedDate < todayKeyStr`
3. **データ永続化・ディープマージ層での自己修復サニタイズ**:
   - `storageService.js` (`loadTasks`): ローカル台帳読み込み時に全タスクの `scheduledDate` を自動サニタイズ。
   - `storageService.js` (`mergeTasksDeep`): クラウド受信・マージの全分岐（空・非空問わず）で `sanitizeTasksDates(merged)` を通し、台帳へ格納される時点で `YYYY-MM-DD` へ恒久固定。
   - `pullDataFromCloud()`: ローカルのタスク数がクラウドのタスク数を下回っている場合、自動でディープマージを発動し、リロード時に即時最新データを引き込んで画面を再描画するフェイルセーフを構築。
4. **モバイルクライアントのアライメント (`mobile.js`)**:
   - `normalizeMobileDateKey()` ヘルパーおよび `sanitizeMobileTasks()` を配備し、モバイル側でも長文Date文字列の流入を遮断・正規化。

## 2. 💡 「知ると面白い、今回の技術の仕組み」解説（エンジニア視点・ユーザー視点）

### 👨‍💻 エンジニア視点：なぜ分散システムにおいて「日付文字列（Date String）」は最も危険な罠なのか？
JavaScriptにおける日付（`Date`）は、内部的には「1970年1月1日UTCからの経過ミリ秒」という単一の数値（タイムスタンプ）です。しかし、これがJSONやスプレッドシートという外部ストレージと行き来するとき、必ず**文字列化（シリアライズ）**されます。

ここに巨大な罠が潜んでいます。
1. **暗黙の文字列変換の差異**:
   Googleスプレッドシートのスクリプト環境（Rhino/V8）で日付型セルを `String(cellValue)` すると、ISO形式（`2026-09-18T00:00:00.000Z`）ではなく、`Fri Sep 18 2026 00:00:00 GMT+0900 (日本標準時)` というプラットフォーム固有のローカル文字列になります。
2. **型安全の幻想と厳格比較（`===`）の破綻**:
   UIレンダラー側が `"2026-09-18"` というフォーマットを前提にして `task.scheduledDate === dateKey` と書いた瞬間、同じ「2026年9月18日」を指していながら文字列が不一致となり、データが忽然と画面から消え去ります。
3. **防衛的プログラミングの真髄**:
   今回配備した `normalizeToLocalDateKey` は、「どんな汚れた日付フォーマットが外から飛滅してきても、必ず内部標準の `YYYY-MM-DD` に仕立て直してからビジネスロジックに渡す」という**防衛的アーキテクチャ（Defensive Architecture）**です。これにより、データソースが外部同期、手動CSVインポート、別タイムゾーンの端末であっても、システムが自己治癒（Self-Healing）して正常稼働を維持します。

### 👤 ユーザー視点（哲生さんへのメリット）：タスクが「確実に見える・光る」究極の安心感
哲生さんにとって、Gendriveは人生と仕事を動かす**「司令塔（Personal OS）」**です。
朝起きた瞬間に「今日やるべきタスク」がデイリー画面に並び、カレンダーを見れば「明日以降のタスクの存在を示すドット（・）」が美しく光っている——この当たり前の安心感が100%取り戻されました。

- **本日（9/18）のタスクが完全復活**:
  朝登録した単発タスク、J PREPの音声・データ作成タスク、リスケタスク、ALL-INタスク、返信タスクがデイリー画面の該当セクションにズラリと復活。
- **カレンダーのドット（・）が全復活**:
  カレンダーの「今日（9/18）」はもちろん、「明日（9/19）」以降、11月中旬までの26件のタスクが存在する日付の下に、青いアクティビティドットが確実に点灯。どの日程にタスクが入っているかが一目瞭然になりました。
- **天才アイデアも11件完全生存**:
  先日登録したバイブコーディングのアイデア11件（T156〜T166）も、サイドバーの「天才アイデアの箱」に完璧に保管されています。
- **リロードするだけで自動最新化**:
  PCでGendriveを再読み込み（F5またはリロードボタン）するだけで、最新のクラウドデータが自動マージされ、一切の消失なく即座に全タスクが立ち上がります。
