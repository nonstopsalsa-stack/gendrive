# Gendrive v1.6.1 リリースノート

## 1. 🔍 事前コード分析・設計・リファクタリング分析

### 現状のコード構造と課題
- **データ構造の断絶**: 従来の Gendrive において、定期タスク（Recurring Tasks）は親オブジェクト1つとして `state.tasks` に常駐し、完了操作を行うと親オブジェクト自身の `executionLogs` 配列へ実行履歴が追記される仕組みでした。このため、マスターボードの「単発タスク」タブや Google スプレッドシートの `SingleTasks` シート、および単発タスクを前提とした各種集計・分析機能には実行実績が一切現れませんでした。
- **集計の二重カウントリスク**: 定期タスク完了時に単発タスクレコードを単純に自動生成（クローン）した場合、デイリーボード（セクションビュー、オールビュー、タイムライン）やヘッダーサマリーにおいて「親の定期タスク」と「クローン単発タスク」の両方が走査対象となり、画面上に同じタスクが2行並んだり、完了件数や実績時間が2倍に跳ね上がるという致命的な副作用が存在しました。
- **アンドゥ・未完了戻しの整合性**: 定期タスクを誤って完了にし、直後のトーストUndoやチェックボックスの再トグル、実行ログの個別削除を行った際、連動生成された単発タスクが孤立して残り続ける不整合リスクがありました。

### 設計方針とアーキテクチャ
1. **クローン単発タスクの自動生成 (`taskCloneHelper.js`)**:
   - 定期タスク完了イベント（PC / モバイル両対応）で親タスクの `executionLogs` を記録した直後に、全属性（ドメイン・部門・PJ・6軸マトリクス・実績時間等）を引き継ぎ、識別子（`isRecurringInstance: true`, `recurringSourceId`, `recurringLogId`）を保持した `taskType: 'single'`, `status: 'completed'` の単発タスクレコードを自動生成して `state.tasks` へ追記。
2. **集計二重カウント防止（最重要防壁）**:
   - **デイリー画面 (`isTaskForSelectedDate`)**: デイリー画面では従来通り親の定期タスクが当日の完了状態を表示するため、`task.isRecurringInstance` をデイリー画面のタスクリストおよびデイリーサマリー集計（残り時間・実績・完了件数）から**完全に除外**。同一タスクの2行重複表示および2倍合算を根本遮断。
   - **将来の分析基盤 (`taskCloneHelper.js`)**: 純粋な単発タスク（`isPureSingleTask`）と定期インスタンス（`isRecurringInstanceTask`）を明瞭に峻別し、重複なくログを抽出できる共通API（`getDeduplicatedTaskLogs`）を整備。
3. **アンドゥ・未完了戻しの完全連動**:
   - トーストのUndo、デイリーでの未完了トグル、実行ログ削除モーダルでのログ削除のいずれの契機でも、親タスクのID・日付・ログIDに紐づくクローン単発タスクを配列から自動連動削除する共通関数（`removeRecurringInstanceSingleTasks`）を確立。

## 2. 💡 「知ると面白い、今回の技術の仕組み」解説（エンジニア視点・ユーザー視点）

### エンジニア視点: 親子モデルとインスタンスモデルのハイブリッド統合（Immutable Event Sourcing Pattern）
一般的なタスク管理システムにおいて、「定期タスク（親・テンプレート）」と「日々の実行実績（子・インスタンス）」をどう保持するかは古典的な難問です。
- **パターンA（親のみ＋ログ配列）**: データがコンパクトで定期設定の変更が容易だが、単発タスク一覧やスプレッドシートなどのフラットな表形式に出力しづらい。
- **パターンB（毎日全件インスタンス生成）**: 日付ごとにタスクオブジェクトを生成するが、未着手定期タスクが日々大量にDBへ溢れかえりストレージと同期負荷が激増する。

今回 Gendrive が採用したのは、両者の利点を極限まで融合させた**「完了時オンデマンド・クローンハイブリッド方式」**です。
未完了の定期タスクは「親オブジェクト1件」として身軽に存在し続け、**「ユーザーが完了した瞬間（実行イベント発生時）」にのみ、単発タスクの完了レコードを決定論的（Deterministic）にクローン生成**します。
さらに、生成された単発タスクには `recurringLogId` と `recurringSourceId` という指紋（外部キー）を刻印しているため、親側でUndoやログ削除が起きた瞬間に O(N) で完全な連動巻き戻しが行われます。

### ユーザー視点: 「習慣の継続率」と「全仕事の実績ログ」が何もしなくても1つに繋がる快感
これまで哲生さんが「毎朝の動画チェック」や「日常のルーチン実務」などの定期タスクをこなしたとき、その記録は定期タスク側のストリーク・達成率にしか反映されず、マスターボードの「単発タスク」タブやスプレッドシートの `SingleTasks` シートには現れませんでした。
そのため、「今日、自分が単発・定期あわせてトータルでどれだけの業務量をこなしたのか」「動画編集事業のプロジェクト全体でどれだけの時間を投下したのか」を単発タスク一覧やスプレッドシートで一元的に振り返ることができませんでした。

今回のアップデートにより、**定期タスクをいつも通り完了するだけで、裏側で自動的に「完了済みの単発タスク」として履歴が蓄積**されます。
デイリー画面ではこれまで通りすっきりと1行のチェック済みタスクとして表示され、実績時間や件数が2倍に狂うことも一切ありません。
マスターボードの「単発タスク」タブを開けば、水色の `🔁 定期` バッジが付いた実行レコードとして整然と並び、スプレッドシートにも即座に同期されます。

## 3. 🌟 Gendrive [v1.6.1] の主要機能・変更点（全機能一覧）

1. **定期タスク完了時の単発タスク自動追記エンジン (PC / モバイル完全対応)**:
   - 定期タスクの完了時（`completeTask`）、親タスクの実行ログ記録と同時に、同一内容を持つ完了済み単発タスク（`taskType: 'single'`, `status: 'completed'`）を自動生成。
   - タイトル、ドメイン大/小、部門大/小、プロジェクト大/小、セクション、時間種別、実績時間（`actMin`）、実績開始/終了時刻、6軸マトリクス評価、優先度、ラベル、タグ、メモ、Obsidianノートの全属性を完全クローン。
   - `isRecurringInstance: true`, `recurringSourceId`, `recurringLogId` の各識別子を付与。
2. **集計二重カウント完全防止エンジン (Dual Count Prevention Engine)**:
   - デイリー画面判定（`isTaskForSelectedDate`）でクローン単発タスクを確実に除外。
   - デイリーボード（セクションビュー、オールビュー、タイムライン、フォーカスビュー、モバイル版）において、同一タスクの2行重複表示を根本防止。
   - デイリーヘッダーサマリー（`renderEtaSummary`）の実績時間・完了件数ループに二重ガードを設置し、合算値が2倍になる現象を完全排除。
   - キャリーオーバーエンジン（`getPastIncompleteTasks`）の未完了繰越候補からクローン単発タスクを除外。
3. **未完了戻し（Undo / トグル / ログ削除）の完全連動パイプライン**:
   - 完了直後のトーストUndo操作時に、生成されたクローン単発タスクを連動して自動削除。
   - デイリー画面等でのタスク再トグル（完了 ➔ 未完了戻し）時に、当日のクローン単発タスクを連動削除。
   - 実行記録タイムラインモーダルからの定期タスク個別ログ削除時（`deleteExecutionLog`）に、該当ログに紐づくクローン単発タスクを連動削除。
4. **マスターボード（Table View）での視覚的識別バッジ**:
   - 「単発タスク」タブの一覧において、定期由来のクローンタスク名の横に `🔁 定期` バッジを美しく表示。
5. **Google Apps Script (GAS) スプレッドシート連携拡張**:
   - `gas_sync_script.js` の `SingleTasks` シート出力ヘッダーおよびデータ行に「定期由来(`isRecurringInstance`)」「親定期ID(`recurringSourceId`)」列を追加。スプレッドシート上でもピボット分析・フィルタリングが可能に。
6. **将来の分析機能（Analytics）向け共通API整備**:
   - 純粋単発タスク判定（`isPureSingleTask`）、定期インスタンス判定（`isRecurringInstanceTask`）、重複排除ログ抽出関数（`getDeduplicatedTaskLogs`）を共通モジュールとして提供。
7. **全自動検証テストスイートの確立 (32/32 PASS + 既存全パス)**:
   - クローン生成、属性完全継承、単発タスク完了時の非増殖、Undo連動削除、トグル連動削除、ログ削除連動、デイリー二重表示防止、繰越除外、重複排除集計、モバイル側連動の全32テストケースを新設し 100% PASS を達成。
