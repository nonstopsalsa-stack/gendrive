## 1. 🔍 事前コード分析・設計・リファクタリング分析

### 問題の背景
習慣化・定期タスクにおいて、「ストリーク（継続日数）の表示が消えたり戻ったりする」「朝開いた瞬間にストリークが0日やハイフン（-）にリセットされる」「連休や同期タイミングでストリークが途切れる」といった問題が発生していた。
これに対し、過去のバージョン（v1.9.9〜v1.9.10等）では「短期ギャップ（最大6日以内）を自律検知して過去ログを架空の日付で自動補完する（`Autonomous Continuity Bridge` / `gapLen <= 6`）」という対症療法的パッチが導入されていた。

### 根本原因の特定
1. **推測・自動補完によるデータ汚染（時限爆弾構造）**:
   - `migrateHabit` や `sanitizeTasksDates`、`mobile.js` 内で、ユーザーが操作していない空白日に対して `note: '継続性ブリッジ自律補完'` や `bridge_log_` といった架空の完了データを勝手に追加・補完していた。
   - これにより、同期タイミングやサニタイズ実行条件の違いによって架空データが生成されたり消去されたりし、ストリーク値が不安定に揺れ動く原因となっていた。
2. **ストリーク計算関数の副作用とステートフル依存**:
   - `calculateStreak` や `getHabitCurrentStreak`、`getTaskCurrentStreak` において、特定日付（`2026-09-22`〜`2026-09-25`）のハードコード救済期間や、不完全な当日判定（朝一番の当日未完了状態で昨日までのチェーンが途切れる判定）が存在していた。
   - 非スケジュール日（土日など平日限定タスクの休日）が「サボり」として扱われ、チェーンが切断されていた。

### 根本解決の設計
1. **推測・自動補完コードの完全切除と架空ログの完全パージ**:
   - `storageService.js` および `mobile.js` から `Continuity Bridge Engine` を完全に切除。
   - 過去に混入した架空補完ログ（`継続性ブリッジ自律補完`）を不可逆排除し、ユーザーの「確定した完了ログ（history / executionLogs）」のみを絶対の真実（Single Source of Truth）として保持。
2. **決定論的ストリーク計算エンジン（純粋関数・ステートレス）の配備**:
   - **確定ルール1（当日未完了バッファ / Grace Period = 1）**: 今日がまだ未完了（朝一番など）でも、昨日まで継続していれば前日までの日数を維持して表示（朝開いた瞬間に0日・「-」にリセットされない）。
   - **確定ルール2（非スケジュール日の保護）**: `isHabitScheduledForDate` / `isTaskScheduledForDate` を活用し、平日限定タスクなどの非スケジュール日（土日など）は「サボり」ではなくスキップとして扱い、チェーンを切断しない。
   - **確定ルール3（実ログ直読）**: `history` 配列および `executionLogs` の日付を過去に向かって厳密にスキャンし、連続日数を決定論的に算出。

## 2. 💡 「知ると面白い、今回の技術の仕組み」解説

### 決定論的ストリーク計算（Deterministic Pure Function）

これまでのストリーク計算は、「ストレージ側で穴埋めパッチを行い、データそのものを改変してストリークを維持させる」という危険なアプローチをとっていました。
しかし、これは「データ層」と「ビュー/算出ロジック層」の責務が混同された典型的なアンチパターンです。

**改修前の構造（対症療法）**:
`ストレージ読み込み` -> `穴がある？` -> `架空の完了データを捏造して追記` -> `ストレージ保存` -> `計算`
（※副作用があり、同期や再読み込みでデータ不整合が発生する時限爆弾）

**改修後の構造（決定論的純粋関数）**:
`ストレージ読み込み` -> `ユーザーの実ログのみを純粋保持`
`ストリーク計算関数(item)` -> `実ログSet抽出` -> `今日/昨日の未完了バッファ` + `スケジュール日の動的判定` -> `確定値を出力`
（※副作用ゼロ。何回呼び出しても、どの端末で実行しても、1ミリ秒の狂いもなく同一の結果が決定論的に導かれる）

### 当日未完了バッファ（Grace Period = 1）のスマートな仕組み
朝起きてアプリを開いた瞬間は、まだ今日の習慣を実行していません。
単純な連続日数の判定を行うと、「今日が未完了だから連続0日」と判定されてしまいます。
新エンジンでは、今日（`i = 0`）について：
- 完了していればストリークに即時加算（`streak++`）
- 未完了であればチェーンを切断せず昨日（`i = 1`）へ判定をパス（前日までの日数を維持表示）
という非破壊バッファを設けることで、ユーザーの継続モチベーションを損なわない設計を実現しています。

## 5. 🚀 リリース後・運用の注意点
1. **確定実ログの保護**:
   - プログラムが勝手に過去日付を追加・補完することは二度とありません。ユーザーが完了ボタンを押した純粋な実績のみが記録・集計されます。
2. **キャッシュの更新**:
   - `sw.js` のキャッシュバージョンを `gendrive-lite-v1917` に更新しているため、PWA/モバイル環境でも自動的に最新エンジンへリフレッシュされます。
3. **本番環境への安全性**:
   - 本番GAS/スプレッドシートへのダミーデータ送信は一切行われておらず、ゼロ汚染が維持されています。
