# Gendrive v1.9.1 リリースノート

## 1. 🔍 事前コード分析・設計・リファクタリング分析

### 現状のコード構造とインシデントの経緯
- **インシデント概要**:
  - v1.8.8（ハビット完了同期改修）、v1.8.9（タスク完了パイプライン改修）、v1.9.0（暗黒化CSS撤廃およびモーダル自動起動解除）を適用した直後、朝 07:45 時点の Gendrive PC環境において、ユーザーが第1セッション（03:00〜06:00）の未消化ハビット（H088「起床〜第1セッションプランニング」）を開始しようとした際、カードが「⏳ 待機中」のまま開始できない（または開始しても完了不能・黒くなる現象の残像）現象が報告されました。
- **徹底原因調査により突き止められた3大構造的欠陥**:
  1. **`moveHabitToTopOfSection` と `saveHabits` の致命的な内部競合（並び順巻き戻りバグ）**:
     - `startHabit` 内で `moveHabitToTopOfSection` により配列先頭へ `splice` 移動させているにもかかわらず、その直後に呼ばれる `saveHabits()` の先頭行に `state.habits.sort((a, b) => (a.sortOrder || 0) - (b.sortOrder || 0));` が存在していました。
     - このため、`splice` で先頭に移動させた配列順序が、直後のソートによって一瞬で元の古い `sortOrder` 順に巻き戻され、内部配列と画面順序の整合性が破壊されていました。
  2. **Optimistic Direct DOM Mutation Guard の不在による画面更新ラグ**:
     - 直前の v1.8.8 / v1.8.9 で「完了処理（`completeHabit` / `completeTask`）」には即時DOM消去ガードが配備されたものの、「開始処理（`startHabit` / `startTask`）」には即時DOM更新ガードが存在しませんでした。
     - 全画面の `innerHTML` ゼロクリア再構築を行う重い `renderApp()` や、15秒ハートビート同期の通信ラグに依存していたため、クリックした瞬間にエメラルドグリーンへ遷移せず、ユーザーには「開始ボタンを押したのに反応しない」「待機中のまま開始できない」と見えていました。
  3. **15秒ハートビート同期（GAS連携）における古い実行中ステータスの競合リスク**:
     - クラウド側に古い実行中タスク（例: 06:07 開始の T206 オンゴーイング プロジェクト）が残存している状態で、ローカルでハビットを開始した直後にバックグラウンド同期（`pullDataFromCloud`）が走ると、`mergeTasksDeep` がクラウドの `in_progress` をローカルへゾンビ復元し、開始したハビットが中断に押し戻される危険性が存在しました。

### 設計方針とアーキテクチャ
1. **Optimistic Direct DOM Mutation Guard（即時DOM実行中遷移ガード）の配備**:
   - `startHabit` および `startTask` 実行時に、全体再描画や非同期通信を1ミリ秒も待たず、対象カード（`.habit-card[data-id="${targetId}"]` / `.task-card`）をその場で直接エメラルドグリーン／シアンの実行中ネオンクラス（`in-progress is-timescale-active`）、ステータスピル（「● 実行中」）、アクションボタン（「✓ 完了」）へダイレクトに書き換えます。
   - 先行して動いていたタスクやハビットも即時に「⏸️ 中断中」「▶ 再開」へ切り替えます。
2. **`saveHabits()` における旧ソート順破壊の完全撤廃と順序再採番の確立**:
   - `saveHabits()` 先頭の `sort((a, b) => (a.sortOrder || 0) - (b.sortOrder || 0))` を撤廃。
   - `moveHabitToTopOfSection` などで整流された実行時配列順を最優先で尊重し、現在の配列順に基づいて連続した `sortOrder`（1..N）を再採番・永続化する強固な順序インテグリティを確立しました。
3. **シングルタスク排他ディープマージ（`mergeTasksDeep` / `mergeHabitsDeep`）の防壁強化**:
   - `mergeTasksDeep` および `mergeHabitsDeep` において、`state.activeHabitId` または `state.activeTaskId` が存在する場合、クラウドから古い `in_progress` が着信しても決して実行中へゾンビ復活させず、安全に `paused` として合流させる相互排他制御を徹底しました。
4. **キャッシュバスターの全面更新 (`?v=1.9.1`)**:
   - `js/config.js`, `index.html`, `mobile.html` の全スクリプトタグおよびCSSリンクを `?v=1.9.1` に更新し、ブラウザキャッシュによる旧コードの残存を根絶しました。

## 2. 💡 「知ると面白い、今回の技術の仕組み」解説（エンジニア視点・ユーザー視点）

### エンジニア視点: Optimistic Direct DOM Mutation（楽観的直接DOM書き換え）と状態永続化の二層アーキテクチャ
モダンなWebアプリケーションにおいて、「ユーザーの操作に対する即時フィードバック」と「永続化ストレージやバックエンドとの同期」は、しばしば競合の温床となります。

これまでの Gendrive では：
```text
[クリック] ➔ [内部状態更新] ➔ [localStorage保存] ➔ [renderApp()で全DOM再構築]
```
というパイプラインを採用していました。この方式は一見シンプルですが、全DOM再構築（`innerHTML` の総入れ替え）には数十ミリ秒のラグがあり、さらにその間に非同期同期（GASハートビート）が挟まると、画面が更新されなかったりフォーカスが外れて「クリックが効かない」ように見えてしまいます。

v1.9.1 では、**「二層同期アーキテクチャ（Dual-Layer Synchronization）」** を導入しました：
```text
[クリック]
   ├── [第1層: Direct DOM Mutation] ➔ 1ミリ秒で該当要素のクラス・ボタン・ピルを直接書き換え（即時ネオン点灯）
   └── [第2層: Persistence & Reconciliation] ➔ 配列順序整流 ➔ localStorage保存 ➔ renderApp()で全体調停
```
第1層により、ユーザーの指先にはクリックした瞬間に「● 実行中」「✓ 完了」が確実に反映され、遅延や画面のチラつきが完全ゼロ化されます。そして第2層がバックグラウンドで安全にソート順やストレージを整流化するため、体験速度とデータ整合性が両立します。

### ユーザー視点: どの時間帯・どのセクションからでも「押した瞬間に確実に動く」安心感
「朝起きて、前のセクションのプランニング習慣を開始したいのに、ボタンを押しても動かない…」「開始できたのか待機中のままなのか分からない」という現象は、1日のスタートにおける集中力を著しく削いでしまいます。

今回の v1.9.1 改修により：
- **どのセクション、どの時間帯であっても、開始ボタンを押した瞬間にカードが鮮やかなエメラルドグリーン／シアンのネオン表示に切り替わります。**
- ピルは即座に「● 実行中」に変わり、ボタンは「✓ 完了」へと遷移し、毎秒のライブタイマーが確実にカウントアップを開始します。
- 先行して動いていたタスクがあれば自動的に「⏸️ 中断中」となり、1画面に複数の実行中が衝突することのない、清潔で安心なシングルタスク集中環境が保証されます。

## 3. 🌟 Gendrive [v1.9.1] の主要機能・変更点（全機能一覧）

| 機能・コンポーネント | 種別 | 詳細・変更点 |
| :--- | :--- | :--- |
| **Optimistic Direct DOM Mutation Guard** | **新規配備** | `startHabit` / `startTask` 実行時に対象カードのDOM（クラス・ピル・ボタン）を1ミリ秒で即座に実行中表示へ直接書き換える即時遷移防壁を配備。 |
| **配列順序インテグリティ保護 (`saveHabits`)** | **根本是正** | `saveHabits()` 先頭での古い `sortOrder` による破壊的ソートを撤廃。`moveHabitToTopOfSection` 等で整流された配列順序に基づいて `sortOrder` を再採番して永続化。 |
| **シングルタスク排他ディープマージ** | **強化防壁** | `mergeTasksDeep` / `mergeHabitsDeep` において、ローカル側のアクティブ状態（`state.activeHabitId` / `state.activeTaskId`）を最優先保護し、クラウドからの古い実行中ゾンビ復活を完全遮断。 |
| **先行タスク・ハビット即時中断連動** | **即時連動** | ハビット開始時に実行中タスクを即座に中断中DOM（「⏸️ 中断中」「▶ 再開」）へ切り替え、タスク開始時にもハビットを即座に中断中へ切り替える完全排他同期。 |
| **全ファイルバージョン統一 (`v1.9.1`)** | **整合統一** | `js/config.js`, `index.html`, `mobile.html`, `app.js` のバージョン表示および全27スクリプトタグ・CSSクエリパラメータを `?v=1.9.1` に完全統一。 |
