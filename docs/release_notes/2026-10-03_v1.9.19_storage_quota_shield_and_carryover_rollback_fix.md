## 1. 🔍 事前コード分析・設計・リファクタリング分析

### 【根本原因の特定】
「前日までの未完了タスク一括取り込みボタンが動作しない / 一瞬動いてもすぐ巻き戻る」「タスク・ハビットの操作が巻き戻る」問題の原因を計測・構造分析した結果、以下の2つの致命的ボトルネックの連鎖によるものであると特定しました。

1. **LocalStorage クォータパンク（5MB上限超過）による UI Freeze**:
   - `createAutoBackupSnapshot()` がタスク・ハビットの全履歴を含むフルスナップショットを最大10世代保持しており、約3〜4MB以上の大容量を常時消費。
   - 一括取り込みボタン実行時、`saveTasks()` の `localStorage.setItem` でブラウザの `QuotaExceededError`（例外）が未捕捉でスローされ、その直後の `renderApp()` や `updateSidebarBadges()` に処理が到達せず、画面がフリーズしていました。
2. **クラウド遅延レスポンス（16秒）とローカル最新データの逆流上書き（Stale Pull Merge）**:
   - Google Apps Script (GAS) への通信レスポンスが 545KB・約16.2秒を要しており、PC側からのプッシュが約22時間タイムアウト・未反映のままになっていました。
   - ローカルで「一括取り込み」を行いタスク日付を「今日」に更新した直後、バックグラウンドの15秒ポーリング（`pullDataFromCloud`）が到着。
   - `hasPendingPush` が true の条件下で「22時間前の古いクラウドデータ」と「ローカルデータ」のディープマージが走り、今日のタスクが過去日付へ巻き戻されていました。
3. **重複リスナーと起動直後の全件タイムスタンプ汚染**:
   - `storageService.js` 末尾に重複した `DOMContentLoaded`, `visibilitychange`, `setInterval` が存在し、不要な多重通信とキューのスタックを誘発。
   - 起動時にベースラインスナップショットが未登録だったため、起動時に無関係な全タスク・ハビットの `updatedAt` が一括更新されていました。

### 【「引き算」による恒久アーキテクチャ設計】
複雑な同期パッチを追加するのではなく、不要・有害なコードを根こそぎ取り除く「引き算」により解決しました。
- **引き算①**: スナップショット世代数を 10件 ➔ **最新2件** へ間引き。さらに `saveTasks`/`saveHabits` を `try/catch` で防護し、万が一のクォータ上限時もスナップショットを自律パージしてメインデータを100%確実に保存する安全シールドを構築。
- **引き算②**: `hasPendingPush || isLocalDirty`（ローカルに未送信の最新変更がある）状態でのクラウドマージ処理を完全撤去。古いクラウドデータによる巻き戻しを物理的に遮断（単方向フロー）。
- **引き算③**: `storageService.js` 末尾の重複リスナー（3箇所）を完全除去。ポーリング間隔を 15秒 ➔ **45秒** へ緩和し、GAS遅延時の通信詰まりを防止。
- **引き算④**: 起動直後にローカルデータのベースラインスナップショットを自動登録し、起動時の全件無駄スタンプ押印を完全根絶。

## 2. 💡 「知ると面白い、今回の技術の仕組み」解説（エンジニア視点・ユーザー視点）

### ⚙️ エンジニア視点：なぜ「古いクラウドデータでマージ」すると巻き戻るのか？
分散システムやPWAにおけるデータ同期で最も危険なアンチパターンは、「**自分が更新中（Dirty状態）のときに、通信遅延で過去に投げたリクエストの古い返戻データを受け取ってマージしてしまうこと**」です。
GASへのリクエストに16秒かかる場合、ユーザーが秒単位で操作した最新状態（＝未完了タスクを今日に移動した状態）があるにもかかわらず、「16秒前の過去の世界」が返ってきます。
これまでは「親切心」から両者をマージ（`mergeTasksDeep`）しようとしていましたが、日付フィールド等の競合解決でタイムスタンプのブレにより過去日付が勝ってしまい、巻き戻りが発生していました。
今回の改修では、**「ローカルに新しい変更があるなら、クラウドからの受信データは一切信用せず捨てる（遮断する）」** という不可逆な単方向原則を徹底したことで、100%確実に巻き戻りを防げるようになりました。

### 👤 ユーザー視点：何が変わったのか？
- **未完了タスクの一括取り込みがノータイムで完了**:
  ボタンを押した瞬間に、前日までのやり残したタスクが迷いなく今日のセッションへ一瞬で移動します。
- **リフレッシュしても絶対に元に戻らない**:
  画面を更新したり、別タブを開いたり、モバイル版を開いたりしても、操作したタスクやハビットが過去の日付や未完了状態へ勝手に巻き戻ることがなくなりました。
- **ブラウザの容量不足エラーがゼロに**:
  バックグラウンドで不要なスナップショットが溜まり続けることがなくなり、ブラウザストレージが常に軽量・クリーンに保たれます。

## 3. 🌟 Gendrive [v1.9.19] の主要機能・変更点（全機能一覧）

1. **🛡️ LocalStorage クォータシールド & 自動パージフォールバック**:
   - `STORAGE_KEYS.SNAPSHOTS` の最大保持数を 10 ➔ 2世代 に圧縮。
   - PC版 (`saveTasks`, `saveHabits`) およびモバイル版 (`saveLocalTasks`, `saveLocalHabits`) にて `QuotaExceededError` ハンドリングを導入。容量上限検知時にスナップショットを自動解放してメインデータを死守。
2. **🚫 Stale Cloud Pull Stale-Merge Barrier（巻き戻し完全遮断）**:
   - `pullDataFromCloud` (PC) および `pullFromCloud` (モバイル) において、ローカルに保留中の変更（`hasPendingPush || isLocalDirty`）がある場合、古いクラウドデータによる上書き・マージを完全バイパス。
3. **🧹 通信ループ重複削除 & ポーリング負荷緩和**:
   - `storageService.js` 末尾の重複リスナー（`DOMContentLoaded`, `visibilitychange`, `setInterval`）を完全削除。
   - バックグラウンドハートビート間隔を 15秒 ➔ 45秒 に緩和。
4. **⏱️ ベースライン初期化 & 不要タイムスタンプ押印防止**:
   - アプリ起動時の `loadTasks`, `loadHabits`, `loadLocalData` にてベースラインを自動マッピングし、未変更データの `updatedAt` 自動書き換えを根絶。
5. **🧪 自動検証テストスイートの完備**:
   - `tests/test_carryover_and_quota_shield.html`
   - `tests/run_carryover_test.ps1` (Headless Edge / CDP自動テスト: 6項目全パス)
   - 既存の56項目ハビットライフサイクルテスト（`run_multi_habit_lifecycle_test.ps1`）も全件パス確認済み。
