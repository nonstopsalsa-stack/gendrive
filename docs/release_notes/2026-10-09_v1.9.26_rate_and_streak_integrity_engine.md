# Gendrive リリースノート v1.9.26: 達成度・ストリーク整合性エンジン (Rate & Streak Integrity Engine)

## 1. 🔍 事前コード分析・設計・リファクタリング分析

### 1-1. 課題・インシデントの根本原因分析
1. **朝の未完了による達成度低下の不整合**:
   - `js/engine/statsEngine.js`（`calcPeriodRate`）および `js/views/tableView.js`（`getTaskPeriodRate`）において、直近 `daysWindow` 日の走査が固定で当日（`i = 0`）から開始されていた。
   - ストリーク計算（`calculateDeterministicStreak`）では「今日未完了なら前日までの実績を維持（`startOffset = 1`）」という健全な猶予期間が適用されていたのに対し、達成度計算側では当日未完了を「サボり・欠落（0回完了）」としてそのまま分母に含めていた。
   - このため、43日連続・46日連続で継続している習慣であっても、朝起きてアプリを開いた瞬間、30日達成度が `29 / 30 = 96.6%`（四捨五入で 97%）、7日達成度が `6 / 7 = 85.7%`（四捨五入で 86%）に不当低下する致命的な不整合が発生していた。

2. **ストリークと達成度の定義乖離**:
   - 連続日数（ストリーク）が対象期間（3日、7日、30日）以上継続している場合、数学的・常識的にその期間の達成度は 100% であるはずだが、期間判定ループにおける境界条件のズレや過去特定日の認識齟齬により、ストリークと達成度の数値が乖離するケースが存在した。

3. **90日達成度と運用期間のギャップ & 定期タスクの分母固定バグ**:
   - Gendriveの現在の運用期間が約46日程度であるため、90日間の確定ログは存在しない。設計上「90日未満の場合は30日達成度の値を表示する」フォールバックが期待されていたが、ハビット側では経過日数（46日分）のみで割る計算となっており、初期2週間の実施頻度差によって30日と90日で10%以上の不整合が発生していた。
   - 定期タスクの `getTaskPeriodRate` においては、経過日数にかかわらず分母が固定の `days`（90等）で割られていたため、運用46日のタスクが全日完了していても最大 `46 / 90 = 51%` にしかならないという数学的欠陥が存在した。

### 1-2. アーキテクチャ設計・リファクタリング方針
- **特定日付パッチの排除（絶対原則遵守）**:
  特定の日付文字列や個別IDへのハードコード救済を一切行わず、純粋関数としての計算エンジン（`recalculateHabitRates`, `getHabitRate`, `getTaskPeriodRate`）のみを根本修正。
- **当日未完了の起点シフト（Yesterday Start）**:
  今日が完了している場合は今日起点（`startOffset = 0`）、今日未完了の場合は昨日起点（`startOffset = 1`）で直近N日を遡る一貫したルールを確立。
- **作成日境界保護（`maxAvailableDays`）**:
  昨日起点にシフトした際、作成日（運用開始日）より前へ遡って未完了判定されることがないよう、`maxAvailableDays = startOffset === 1 ? Math.max(1, elapsedDays - 1) : elapsedDays` を配備。
- **ストリーク連携保証**:
  現在の確定ストリーク日数が対象期間または有効日数以上（`streak >= daysWindow || streak >= effectiveDays`）であれば無条件に 100% を返却。
- **90日フォールバック＆有効日数割**:
  運用90日未満の場合は 30日達成度の値を透過的に返却。タスクの分母は `Math.min(days, maxAvailableDays)` で割るよう是正。

## 2. 💡 「知ると面白い、今回の技術の仕組み」解説（エンジニア視点・ユーザー視点）

### エンジニア視点: 「時間軸スライディングウィンドウにおける因果律と起点制御」
統計計算において「今この瞬間（Today）」の扱いは極めて繊細です。
一日の始まりである「朝」においては、まだ今日の行動が行われていないのは物理的に必然です。この「未着手」を「不履行（未達成）」として扱ってしまうと、前日までの完璧な継続実績に対してシステムがペナルティを科すことになり、ユーザー体験を損ねます。
今回採用した **「起点適応型スライディングウィンドウ（Adaptive Offset Windowing）」** は：
```javascript
const isTodayDone = isEntryDone(todayKey);
const startOffset = isTodayDone ? 0 : 1;
const maxAvailableDays = startOffset === 1 ? Math.max(1, elapsedDays - 1) : elapsedDays;
const effectiveDays = Math.max(1, Math.min(daysWindow, maxAvailableDays));
```
という数学モデルに基づきます。
「今日完了していれば、今日を含む直近N日を評価する」「今日がまだなら、昨日を含む直近N日を評価する」。
さらに、昨日を起点とした際に「運用開始日より前の存在しなかった過去日」までループが踏み込まないよう、上限を `elapsedDays - 1` に束縛することで、新規作成タスク・ハビットでも境界値エラーを起こさない完璧な純粋計算を実現しました。

### ユーザー視点: 「朝起きた瞬間から、あなたの努力が100%認められる安心感」
「毎日休まず43日も歯磨きを続けているのに、朝アプリを開いたら達成度が97%になっていてモヤモヤする……」
この違和感が、今回の改修で完全にゼロになりました。
「朝起きた時点では、まだ今日の分をやっていなくて当たり前」。システムがその当たり前の事実を賢く認識し、昨晩までの完璧な継続を讃えて **堂々と100%を表示** します。
そして今日の分を完了させた瞬間に、今日を含めた最新の100%へとバトンが渡されます。
あなたのストリーク（連続日数）と達成度バーは、今日から完全にシンクロして動きます！

## 3. 🌟 Gendrive [v1.9.26] の主要機能・変更点（全機能一覧）

1. **朝一番の未完了による達成度低下の完全是正 (Yesterday-Start Engine)**
   - 当日未完了のハビット・タスクについて、今日を含めずに「昨日」を起点として直近3日/7日/30日達成度を計算。
   - 当日完了した瞬間に今日起点へと滑らかに切り替わり、常に最新実績を反映。
   - 朝起きてスコアボードを開いた瞬間に 97% や 86% へと縮退する現象を根絶。

2. **ストリークと達成度の完全一致 (100% Guaranteed Alignment)**
   - 対象期間の日数（3日/7日/30日）が現在の確定ストリーク日数以下である場合、数学的に無条件で 100% を算出。
   - 「43日連続なのに30日達成度が100%にならない」「7日連続なのに7日達成度が86%になる」といった表示矛盾が完全に解消。

3. **90日達成度の30日自動フォールバック (Operational 90-Day Fallback)**
   - 運用開始90日未満のハビットおよびタスクについて、90日達成度に30日達成度と同一の値を自動表示。
   - 運用開始初期のデータ不足による歪み（0%や乖離）を完全に防ぎ、一貫したKPIを提示。

4. **定期タスクにおける分母固定（90日割）計算欠陥のゼロベース是正**
   - `tableView.js` の `getTaskPeriodRate` において、分母が固定日数で割られていた構造的バグを修正。
   - 運用開始からの経過日数（`getTaskElapsedDays`）と対象期間の小さい方（`effectiveDays`）で正しく割る設計へ刷新。

5. **厳格な回帰テスト・検証スイートの配備**
   - 新規ユニット＆実データ再現テスト `tests/test_v1925_rate_streak_integrity.ps1` および `tests/test_v1925_runner.js` を配備。全16項目のテストケースが全て [PASS] することを確認。
