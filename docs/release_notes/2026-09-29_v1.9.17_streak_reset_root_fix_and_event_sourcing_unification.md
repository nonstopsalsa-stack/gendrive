## 1. 🔍 事前コード分析・設計・リファクタリング分析

### 問題の背景
継続スコアボードのストリーク（連続日数）が何度もリセットされる現象が繰り返し発生していた。過去のパッチ対応（v1.9.9〜v1.9.11）では症状を一時的に抑えるに留まり、根本原因は未解決のまま複数の絆創膏コードが積み重なった状態だった。

### 根本原因の特定
調査の結果、根本原因は **`app.js` の `sanitizeDailyState()` 関数**にあることを特定した。

アプリ内のハビット history データは、旧フォーマット（オブジェクト形式 `{YYYY-MM-DD: true}`）から新フォーマット（Event Sourcing 配列形式 `["YYYY-MM-DD", ...]`）への移行（`MIGRATION_V2`）が完了していたにもかかわらず、`sanitizeDailyState` 内の「完了済み判定」ロジックがオブジェクト形式のみに対応していた。

この結果、**配列形式の history を持つ全ハビット（移行済みの全ハビット）**は、毎朝・毎分（`updateHeaderAndStatus`）・スリープ復帰時（`visibilitychange`）に「今日完了記録なし」と誤判定され、`status = 'uncompleted'` に強制書き換えされていた。

history 配列自体は消えないため「データは存在するが表示がリセットされる」という特徴的な症状を示していた。

### 副次的問題（絆創膏コードの洗い出し）
| # | 問題箇所 | 内容 |
|---|---------|------|
| A | `app.js` L.1167（旧） | `completeHabit` で `history = {}` 初期化（オブジェクト形式） |
| B | `tableView.js` L.559, L.2010（旧） | ハビット単体・一括複製時に `history = {}` 初期化 |
| C | `recurrenceEngine.js` L.17, 53, 64（旧） | `weekly_goal` 判定・週集計が配列 history に非対応 |
| D | `tableView.js` L.2083（旧） | `getHabitCurrentStreak` の二重定義（`statsEngine.js` と重複） |
| E | `app.js` L.4103（旧） | `habit_flow_ghost_fix_20260819_v1` 絆創膏パッチが残存 |

## 2. 💡 「知ると面白い、今回の技術の仕組み」解説

### Event Sourcing パターンとは

Gendrive のハビット履歴管理には **Event Sourcing** と呼ばれる設計パターンが採用されている。

**旧設計（オブジェクト形式）**
```javascript
history = { "2026-09-28": true, "2026-09-29": true }
```
特定日付をキーとするオブジェクト。「ある日に完了したか」を O(1) で参照できるが、JavaScript のオブジェクトはキーが文字列でも数値でも参照できてしまうため意図しないバグを生みやすい。

**新設計（Event Sourcing 配列形式）**
```javascript
history = ["2026-09-28", "2026-09-29"]
```
完了した日付を文字列の配列として追記していく。追記のみ（削除は filter で行う）という「イベントの追記のみ」の原則が Event Sourcing の本質。`Array.includes()` で存在確認でき、ソートすることで時系列順が自然に保たれる。

### 問題の構造

移行は `storageService.js` の `MIGRATION_V2` フラグで一度だけ実行されるが、移行後のコードが**全ファイルで一貫して配列形式に対応していなかった**ことが問題だった。特に `sanitizeDailyState` の「翌朝リセット」ロジックは毎朝実行されるため、誤判定の影響が蓄積した。

### 修正のアプローチ：透過アクセスヘルパーの導入

各ファイルにバラバラに書かれていた history 形式判定を、**統一ヘルパー関数**に集約した。

```javascript
// recurrenceEngine.js に追加
function _isHabitDoneOnDate(habit, dateKey) {
  if (!habit || !habit.history || !dateKey) return false;
  if (Array.isArray(habit.history)) return habit.history.includes(dateKey);
  // オブジェクト形式（後方互換）
  const val = habit.history[dateKey];
  return val === true || (typeof val === 'object' && val !== null && Boolean(val.done));
}

// app.js sanitizeDailyState に追加
const isHabitDoneToday = (h) => {
  if (Array.isArray(h.history)) return h.history.includes(todayKey);
  return Boolean(h.history && (h.history[todayKey] === true || h.history[todayKey]?.done));
};
```

これにより、旧データ（オブジェクト形式）が残っていても新データ（配列形式）でも**同一ロジックで正しく動作する後方互換性**を確保した。

## 3. 🌟 Gendrive v1.9.17 の主要機能・変更点

### 🔴 根本修正（バグフィックス）

#### [Fix-1] 継続スコアボード ストリーク永久リセット問題の根本修正
- **対象:** `app.js` `sanitizeDailyState()` 関数
- **修正内容:** 「今日完了済みか」の判定ロジックを配列・オブジェクト両形式対応に統一
- **効果:** 毎朝・スリープ復帰時に完了済みハビットのステータスが `uncompleted` に誤書き換えされる現象を根絶
- **影響範囲:** 全ハビットの継続スコア表示・ストリーク計算

#### [Fix-2] `completeHabit` の history 初期化形式統一
- **対象:** `app.js` `completeHabit()` 関数
- **修正内容:** `history = {}` → `history = []` に変更（Event Sourcing 配列形式に統一）
- **効果:** ハビット完了操作時のデータ整合性確保

#### [Fix-3] ハビット複製時の history 初期化形式統一
- **対象:** `js/views/tableView.js` `duplicateSingleItem()` / 一括複製処理
- **修正内容:** `history = {}` → `history = []` に変更（2箇所）
- **効果:** 複製されたハビットが正しい配列形式で初期化され、ストリーク計算が正常に動作

#### [Fix-4] `recurrenceEngine.js` の配列形式 history 対応
- **対象:** `js/engine/recurrenceEngine.js`
- **修正内容:** 先頭に `_isHabitDoneOnDate()` ヘルパーを追加し、`weekly_goal` 判定・週集計を配列対応に統一
- **効果:** `weekly_goal` 型ハビットの達成判定・週集計・スケジュール表示が正確に動作

### 🟡 クリーンアップ（技術的負債解消）

#### [Phase 2-A] 重複関数 `getHabitCurrentStreak` を削除
- **対象:** `js/views/tableView.js` L.2083（旧）
- **修正内容:** `statsEngine.js` に正規定義済みの `getHabitCurrentStreak` の二重定義を削除
- **効果:** 関数定義の競合による予期しない上書きを防止

#### [Phase 2-B] 絆創膏パッチコード `habit_flow_ghost_fix_20260819_v1` 削除
- **対象:** `app.js` L.4103（旧）
- **修正内容:** 2026年8月に追加された「ゴーストクリーンアップ」一時パッチを削除
- **効果:** 不要な起動時処理の排除。根本原因修正（Fix-1）により完全に不要になった。
