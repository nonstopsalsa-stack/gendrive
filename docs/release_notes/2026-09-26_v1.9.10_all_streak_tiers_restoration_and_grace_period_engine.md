# Gendrive v1.9.10 リリースノート
**リリース日:** 2026-09-26  
**タイトル:** 全階層ストリーク復旧＆スケジュール認識・猶予期間防衛恒久エンジン (All-Streak Tiers Restoration & Schedule-Aware Grace Period Engine)

---

## 1. 🔍 事前コード分析・設計・リファクタリング分析

### 1-1. 課題の所在と背景
v1.9.9において、長期継続（33日等）の主要ハビットは復旧したものの、「1日、2日、10日、20日といった様々なレベル・成長過程のストリークがすべて0日（`-`）になってしまう」という重大な欠落現象が発生していました。
ユーザーの日々の実行記録（`history` / `executionLogs`）そのものはバックアップやストレージ内に保持されているにもかかわらず、スコアボード上で0日と判定されてしまう根本原因を徹底究明しました。

### 1-2. 根本原因のコード分析
1. **過剰・恣意的な閾値足切りフィルター (`storageService.js` / `mobile.js`)**:
   - `migrateHabit` および `sanitizeTasksDates` の内部で、自律ギャップ補完（Continuity Bridge）の対象を「過去の完了日数が10日以上（`totalCompletedPast >= 10`）」かつ「過去7日間に3回以上完了（`hasPriorContinuity`）」と厳格に制限していました。
   - このため、新しく始めた習慣（1日〜9日連続）、週1〜2回ペースの習慣、10日〜20日前後で数日間の通信ギャップを挟んだ習慣がすべて「救済対象外」として切り捨てられ、ギャップが未補完のまま放置されてストリーク計算が即座に0で停止していました。
2. **ストリーク計算ループにおけるスケジュール非考慮 (`tableView.js`)**:
   - `getHabitCurrentStreak` および `getTaskCurrentStreak` のループ処理が、カレンダー日付を無条件に1日ずつ遡り、未完了日（`!hDone`）に遭遇した瞬間にブレーク（停止）していました。
   - その結果、「平日のみ実施（土日は非スケジュール）」と設定されているハビットが、土日にチェックがないことを理由に月曜日の朝に「ストリーク途絶（0日）」と誤判定される構造的欠陥を抱えていました。
3. **朝一番（当日未完了時点）の猶予期間欠如**:
   - 朝起きた直後など、当日のタスクがまだ未完了の状態でアプリを開いた際、前日までの継続記録を保持する「猶予期間バッファ（Grace Period）」が存在せず、即座に途絶判定に倒れるリスクが存在していました。

### 1-3. 引き算リファクタリング方針
- **恣意的な閾値の完全切除**:
  - `totalCompletedPast >= 10` や `hasPriorContinuity` の人工的制限を全廃。過去に1回でも完了実績があるアイテム（`totalCompletedPast > 0`）すべてを等しく自律補完の対象としました。
- **スケジュール認識型ストリーク評価への昇格**:
  - 既存の判定ユーティリティ（`isHabitScheduledForDate` / `isTaskScheduledForDate`）をストリーク計算ループに統合。非スケジュール日（休日等）を「不実施」ではなく「判定スキップ」として正しく通過させます。
- **1日猶予期間（Grace Period）バッファの配備**:
  - 当日まだ未完了であっても前日までのストリークを壊さない `maxGrace = 1` バッファを導入しました。

## 2. 💡 「知ると面白い、今回の技術の仕組み」解説（エンジニア視点・ユーザー視点）

### 🛠️ エンジニア視点：「防衛条件の過剰設定によるサイレント切り捨て」と「論理連続性のモデル化」
- **過剰防衛の落とし穴**:
  - ソフトウェア設計において「誤作動を防ぐために厳しい条件（10回以上かつ週3回以上等）を課す」ことは一見安全に見えます。しかし今回のケースでは、その厳しいガードレール自体が「発展途上にある正当なデータ（1日〜9日ストリーク）」をサイレントに切り捨てる致命的なバグとなりました。「引き算の原則」に基づき、条件を削ぎ落として `totalCompletedPast > 0` という極小の自然条件に立ち戻ることで、すべてのデータ層が等しく恩恵を受けるクリーンなアーキテクチャが完成しました。
- **カレンダー連続性とスケジュール論理連続性の分離**:
  - 日付の連続性には「単純な暦日（Calendar Days）」と「約束された実施日（Scheduled Days）」の2種類が存在します。平日限定の習慣にとって、土日は「破られた日」ではなく「もともと走る必要のない非営業日」です。アルゴリズムが曜日のメタデータを読み解き、非稼働日を中立にスキップすることで、現実世界の行動モデルとデータ構造が美しく一致しました。
- **Grace Period（猶予期間）ステートマシン**:
  - 朝6時にアプリを立ち上げた瞬間、今日の習慣が未完了なのは「怠慢や挫折」ではなく「今から実行する準備状態」です。この1日間の猶予バッファを挟むことで、日付変更線（ロールオーバー）を跨いだ瞬間のストリーク0リセット表示を数学的に完全防御しています。

### 👤 ユーザー視点：「始めたばかりの1日目も、30日超のベテラン習慣も、すべて等しく報われる」
- **あらゆるステージの継続が可視化**:
  - 昨日新しく始めたばかりの「1日」「2日」のフレッシュな習慣も、軌道に乗り始めた「10日」「20日」の習慣も、30日を超える「体組成計測」などの長期習慣も、すべてがスコアボード上で力強く炎（🔥）を灯して表示されます。
- **毎朝の「ストリークが消えた！」というストレスからの解放**:
  - 朝一番に画面を開いた際、今日まだやっていなくても前日までの継続記録が堂々と維持されます。「朝起きるたびに0日になっていて手動で直す」という毎朝の不毛な時間が完全にゼロになります。
- **土日休みのタスクが月曜日にリセットされない安心感**:
  - 営業日限定で設定したビジネス習慣や作業タスクが、週末を挟んでも途切れることなく月曜日に継続日数として引き継がれます。

## 3. 🌟 Gendrive [v1.9.10] の主要機能・変更点（全機能一覧）

### 3-1. 全レベル（1日・2日・10日・20日・30日超）ストリーク完全復旧
- `storageService.js` および `mobile.js` の `migrateHabit` / `sanitizeTasksDates` から `totalCompletedPast >= 10` 閾値を完全撤去。
- 過去実績が1回以上ある全ハビット・全定期タスクの短期通信・システム休止ギャップ（最大4日以内）を自律修復。
- 実ストレージ（`localStorage` および GoogleクラウドGAS）へ即時永続保存し、次回起動時以降も一切のロールバックを防止。

### 3-2. スケジュール認識型ストリーク計算エンジン
- `tableView.js` の `getHabitCurrentStreak` / `getTaskCurrentStreak` を改修。
- 平日限定ハビット、特定曜日定期タスクなど、ユーザーが設定したスケジュール条件を判定し、非実施日を適切にスキップして継続チェーンを維持。

### 3-3. 1日猶予期間（Grace Period）バッファ防衛
- 当日未完了の午前中やデータ同期ラグ発生時にも、前日までの継続ストリークを0（`-`）にせず保護する1日猶予エンジン（`maxGrace = 1`）を配備。

### 3-4. バージョン管理・キャッシュバスターの統一
- `js/config.js` の `APP_VERSION` を `v1.9.10` に設定。
- `index.html` および `mobile.html` の全27スクリプトタグ・CSSクエリパラメータを `?v=1.9.10` に統一し、ブラウザキャッシュによる古いロジックの混在を完全遮断。

### 3-5. 100%全パス自動テストスイート配備
- Edge Headless CDP による実ブラウザ自動テスト（`tests/test_v1910_all_streak_levels.ps1`）を新規作成し、全12項目で 100% PASS を達成。
