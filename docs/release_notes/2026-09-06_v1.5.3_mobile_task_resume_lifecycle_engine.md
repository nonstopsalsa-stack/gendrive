# Gendrive リリースノート (v1.5.3)

**リリース日**: 2026-09-06  
**バージョン**: v1.5.3  
**テーマ**: スマホ版タスク・ハビット中断・再開ライフサイクルエンジンの完全刷新・複数中断保持と排他再開アーキテクチャ (Mobile Task & Habit Pause-Resume Lifecycle Engine & Multi-Paused Retention)

---

## 1. 🔍 事前コード分析・設計・リファクタリング分析

### 課題の根本原因分析
v1.5.2 における「タスク中断後に再開できない」「中断中タスクが画面から消失する」現象をコードレベルで徹底追跡した結果、以下の4つの複合的構造障害を特定・解明した。

1. **ローカルストレージキーの不一致によるタスク永続化の断絶**:
   - PC版コア (`app.js`) がタスクデータを `habit_flow_tasks_v3` で保存・読み込みしていたのに対し、`mobile.js` の `STORAGE_KEYS.TASKS` が `gendrive_tasks_v2` に書き換わっていた。
   - これにより、スマホ版でリロードやページ再訪、初期化が走るたびにPC版とデータが乖離し、正しく状態が復元されない障害となっていた。
2. **Sticky Active Bar における排他判定の構造的欠陥**:
   - `renderStickyActiveBar()` 内の判定ロジックが `if (activeHabit) { ... } else if (activeTask) { ... }` の優先順位固定になっていた。
   - 以前にハビットを中断して `activeHabitId` が残存していると、その後タスクを開始・中断しても `activeHabit` 側のレンダリングが優先され、タスクの実行・中断バーが一切画面に描画されない「画面上での再開不可能状態」が発生していた。
3. **リスト描画フィルタによる「中断中タスク」の完全消滅**:
   - `renderList()` 内で、上部バーにピン留めされるタスク（`topTaskId`）をリストから一律除外（`excludeTaskId = topTaskId`）していた。
   - さらに、上部バーがハビットによって覆い隠されている場合、タスクは上部バーにも出ず、カードリストからも除外され、画面全体のどこにも存在しなくなる致命的なUIロストを引き起こしていた。
4. **カード内アクションボタンのイベントバブリング干渉**:
   - カード本体に `onclick="startTask('...')"` が設定されている一方で、カード内の各ボタンにも個別のクリックハンドラが設定されていた。
   - `event.stopPropagation()` が付与されていなかったため、ボタン押下時にカード全体のタップイベントが重複発火し、意図せぬ状態遷移や二重起動の競合が発生していた。

### 設計・リファクタリング方針
- **Single Active, Multi-Paused アーキテクチャの確立**:
  - 実行中（`in_progress`）はシステム全体で常に最大1件（タスク/ハビット排他）。
  - 中断中（`paused`）は手動中断・他項目の開始（Auto-pause）により複数件安全に共存可能。
- **Sticky Active Bar の動的プライオリティ・ルーティング**:
  - 「実行中（`in_progress`）の項目」を最優先で表示。
  - 実行中が存在しない場合のみ、「直近に中断（`paused`）された項目」を `PAUSED` モードで待機表示。
- **リスト内カードの常時アクセス保証（アクセシビリティの回復）**:
  - `renderList()` では「現在実行中（`in_progress`）」のタスクのみをリストから除外し、中断中（`paused`）のタスクはすべてリスト内に保持。
  - リストカード上に「⏸️ 中断中」ステータスバッジと「▶ 再開」ボタンを常時提供し、どの画面階層からでも確実に再開可能にした。
- **ストレージキーの完全同期とレガシー自動マイグレーション**:
  - `STORAGE_KEYS.TASKS = 'habit_flow_tasks_v3'` に完全同期。旧キー `gendrive_tasks_v2` が存在する場合は初回読込時に自動吸い上げ・移行するフェイルセーフを実装。

## 2. 💡 「知ると面白い、今回の技術の仕組み」解説（エンジニア視点・ユーザー視点）

### 🛠️ エンジニア視点：Single Active / Multi-Paused 状態遷移マシンとプライオリティ・レンダリング
```
                      ┌────────────────────────────────────────┐
                      │              未着手 (uncompleted)       │
                      └──────────────────┬─────────────────────┘
                                         │ startTask()
                                         ▼
   ┌──────────────────────────────────────────────────────────────────────────────┐
   │                         実行中 (in_progress)                                  │
   │   ※ システム全体で常に最大1件！ 新規開始時は先行アイテムを auto-pause 遷移       │
   └───────────────┬───────────────────────────────────────────────┬──────────────┘
                   │ pauseTask() / 他項目開始(Auto-pause)           │ completeTask()
                   ▼                                               ▼
   ┌───────────────────────────────────────────────┐     ┌────────────────────────┐
   │               中断中 (paused)                  │     │     完了 (completed)    │
   │  ※ 複数アイテムが同時に paused 状態で待機可能    │     └────────────────────────┘
   │  ※ accumulatedSeconds に実績秒数を正確に累積   │
   └───────────────┬───────────────────────────────┘
                   │ startTask() [▶ 再開]
                   └───────────────────► (実行中へ復帰・何度でも反復可能)
```
- **動的プライオリティ・レンダリング**:
  従来の「ハビット優先の if-else」から、「状態（Status）優先」の評価関数へと昇華させました。
  ```javascript
  // 1. 実行中(in_progress)を最優先探査
  let primaryItem = tasks.find(t => t.id === mState.activeTaskId && t.status === 'in_progress')
                 || habits.find(h => h.id === mState.activeHabitId && h.status === 'in_progress');
  // 2. 実行中がなければ直近の中断中(paused)アイテムを探査
  if (!primaryItem) {
    primaryItem = tasks.find(t => t.id === mState.activeTaskId && t.status === 'paused')
               || habits.find(h => h.id === mState.activeHabitId && h.status === 'paused');
  }
  ```
  これにより、タスクとハビットが互いの描画を握りつぶす競合が100%根絶されました。
- **イベントバブリングの防壁**:
  リストカード内のボタンに `event.stopPropagation()` を徹底配置し、DOMイベントのバブリングによる予期せぬ多重発火を完全に遮断しました。

### 📱 ユーザー視点：迷子ゼロ。何度中断しても、いつでも1タップで復帰できる心地よさ
- **「あれ、さっき中断したタスクどこ行った？」がゼロに**:
  電話や来客でタスクを一時停止したあと、別のハビットを少しやっても、さっきのタスクが画面から消え去ることはもうありません。
- **カードの横に「▶ 再開」ボタンがいつでもスタンバイ**:
  中断中のタスクは、リストの中に「⏸️ 中断中」という分かりやすいバッジとともに残り続けます。再開したいときは、そのカードの「▶ 再開」ボタンを押すだけで、直ちにタイマーが動き出し、画面トップのバーにもアクティブ表示されます。
- **マルチタスクもストレスフリー**:
  タスクAを実行中にタスクBを新しく開始すると、タスクAは自動的に安全に中断（Auto-pause）され、作業実績秒数もしっかり記録されます。タスクBが終わったら、リストからタスクAの「▶ 再開」を押すだけで、続きからシームレスに再スタートできます。

## 3. 🌟 Gendrive Lite [v1.5.3] の主要機能・変更点（全機能一覧）

### 📱 スマホ版（Mobile Lite）機能改修・強化
1. **タスク中断・再開ライフサイクルの完全修復**:
   - `startTask()` および `pauseTask()` による中断・再開の往復が何度でも確実に動作。
   - 中断時（`paused`）の実績時間（`accumulatedSeconds`）を秒単位で高精度に維持・累積。
2. **複数中断保持（Multi-Paused Retention）のサポート**:
   - 手動中断および自動中断（Auto-pause）により、複数の中断タスク・ハビットが安全に共存可能。
   - 中断中の全アイテムがリスト内に保持され、それぞれ個別の「▶ 再開」ボタンからワンタップ復帰可能。
3. **Sticky Active Bar の優先描画エンジンの刷新**:
   - ハビットとタスクのどちらかが実行中の場合、実行中アイテムを最優先でトップバーにピン留め表示。
   - 実行中アイテムがない場合、直近の中断アイテムを「⏸️ PAUSED」としてトップバーに待機表示。
4. **カードリスト描画の改善とアクセシビリティ向上**:
   - 実行中アイテムのみをリストから除外し、中断中アイテムはリスト内に明示的に残留表示。
   - ボタン操作時のイベントバブリング遮断（`stopPropagation`）により、誤タップ・二重発火を根絶。
5. **ストレージキー同期とデータ保護**:
   - PC版コアと完全に一致する `habit_flow_tasks_v3` を採用。
   - レガシーキー（`gendrive_tasks_v2`）からの自動移行コードを実装し、既存データを保護。
6. **PWAキャッシュバスターの同期（v153）**:
   - Service Worker の `CACHE_NAME = 'gendrive-lite-v153'` および全アセットのクエリパラメータを `20260906_v153` に更新し、スマホ実機での即時更新を保証。

### 💻 PC版および共通エンジン
1. **バージョン定義の同期**:
   - `js/config.js` の `APP_VERSION` を `v1.5.3`、バージョン名を「Mobile Task Resume Engine & Multi-Paused Retention」に更新。
   - `index.html` および `mobile.html` のバージョンカプセルバッジを `v1.5.3` に統一。
