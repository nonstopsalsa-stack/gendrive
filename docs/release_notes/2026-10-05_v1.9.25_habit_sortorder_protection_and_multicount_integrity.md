# Gendrive リリースノート - v1.9.25

本リリースノートは、ハビット一覧の並び順（sortOrder）の恒久保護、および1日n回ハビットのカウント算出整合性の確立（孤立キャッシュ排除）に関する改修内容をまとめたものである。

---

## 1. 🔍 事前コード分析・設計・リファクタリング分析

### (1) ハビット一覧の並び順（sortOrder）崩れ問題の構造分析
- **事象**: マスター一覧でユーザーが意図して整えたハビットの並び順（`sortOrder`）が、カードを1回「▶ 開始」した直後に勝手に崩れる。
- **根本原因**:
  1. `app.js` の `startHabit` 内で `moveHabitToTopOfSection(targetId)` が無条件実行され、配列内で該当ハビットをセクション先頭へ `splice` 移動していた。
  2. 直後の `saveHabits()`（`storageService.js`）において、配列の現在インデックスで `h.sortOrder = idx + 1` と全件の `sortOrder` を上書きしていた。
  3. このため、ユーザーがドラッグ＆ドロップやマスター画面で確定させた順序が不可逆的に破壊されていた。
- **設計改善**:
  1. `startHabit` から `moveHabitToTopOfSection` の呼び出しを完全撤廃。
  2. `saveHabits()` での無条件な再採番を撤廃し、未設定・欠損時のみのフォールバック採番へ縮小。ユーザーが明示的に操作した `sortOrder` を恒久的に固定・保護。

### (2) 1日n回ハビットのカウント誤表示（未実施で2/2回 → 完了で1/2回）の構造分析
- **事象**: 1日2回のハビットが、朝起きて未実施なのに「⚡ 2/2回」と表示され、1回完了ボタンを押すと「⚡ 1/2回」に変わる。
- **根本原因**:
  1. 前日2回完了時にオブジェクトへ保存された `habit.todayCount = 2` が日付情報を持たない孤立キャッシュとして残存。
  2. 翌朝、当日の `executionLogs` や `history` が空の状態で `getHabitDayCount(habit, dateKey)` を呼ぶと、ステップ4の `habit.todayCount` にフォールバックし、前日の `2` を当日のカウントとして誤認していた。
  3. 1回目の完了ボタンを押すと `habit.history` が配列化され、配列の判定（`includes(todayKey)`）が `false` ➔ `return 0` を返すため、`0 + 1 = 1` が計算されて「1/2回」に逆転していた。
- **設計改善**:
  1. `getHabitDayCount` から `habit.todayCount` へのフォールバックを完全撤廃。指定日付（`dateKey`）の実ログ（`executionLogs`）および `history[dateKey]` のみを真実（Single Source of Truth）として算出。
  2. `storageService.js` の `migrateHabit` において、日付変更時や当日実ログ不在時に前日の孤立 `todayCount` を安全に破棄（`delete h.todayCount`）。
  3. 0回（未実施） ➔ 1回 ➔ 2回（完了達成）の一貫した状態遷移を確立。

## 2. 💡 「知ると面白い、今回の技術の仕組み」解説（エンジニア視点・ユーザー視点）

### エンジニア視点: Event Sourcing（実ログ主義）とローカルキャッシュのライフサイクル乖離の克服
ソフトウェア設計において、**「タイムラインのイベントログ（事実）」** と **「画面表示の最適化のために保持されたショートカット（キャッシュ）」** が混在すると、キャッシュが古い状態（Stale State）のまま生き残った際に「事実と異なる表示」が発生します。

今回の 1日n回ハビットのカウント問題は、まさにこの典型例でした。`habit.todayCount` は日付属性を持たない単なるスカラー値であったため、日を跨いだ瞬間に「昨日の値」から「危険な孤立データ」へと変貌していました。
今回の改修では、不要なキャッシュへの依存を断ち切り、**指定日付（`dateKey`）に合致する `executionLogs`（実ログイベント）を唯一の真実（Single Source of Truth）** としてカウントを導出するピュアな関数型データパイプラインを確立しました。これにより、キャッシュ不整合という概念そのものを消滅させました。

### ユーザー視点: 「自分の並べ替えた順序が絶対に崩れない」安心感と信頼性
毎朝のタスク・ハビット管理において、自分が並べ替えたマスターの順番通りに整然とカードが並んでいることは、認知負荷を最小化する上で極めて重要です。
これまでは「開始」ボタンを押した瞬間にシステムが気を利かせて一番上に引っ張り上げようとした結果、裏側で全体の並び順インデックスが書き換わってしまっていました。
今回の是正により、**「あなたが決めたハビットの順番は、何が起きても1ミリも動かない」** という絶対の不変性が保証されます。
