# Gendrive v1.8.8 リリースノート

## 1. 🔍 事前コード分析・設計・リファクタリング分析

### 現状のコード構造とインシデントの経緯
- **インシデント概要**:
  - 朝 06:03 頃、Gendrive PC版においてユーザーが「朝ジャーナル記入（H043）」を実行し、「✓ 完了」ボタンを押下したものの、画面上のカードが「● 実行中」「✓ 完了」のまま残り続け、消えないという事象が発生しました。
  - 前日（2026-09-20）の v1.8.7 で同様の「朝食後 キッチンリセット（H019）」巻き戻りインシデントに対応していたものの、別のハビット（H043）で再発したように見えたため、緊急の徹底原因究明を実施しました。
- **調査によって判明した驚くべき真実**:
  - Google Apps Script（GAS）上の本番クラウドデータを調査スクリプトで直接抽出・検証したところ、`H043` は `status: "completed"`, `startTimestamp: null`, `history["2026-09-21"].done = true`, `count = 3` として**クラウドおよび内部ストレージに完全に記録・保存されていました**。
  - すなわち、**データは正常に完了・送信されていたにもかかわらず、画面（DOM）の再描画が行われず、カードが実行中カードとして視界に取り残されていた**ことが判明しました。
- **根本原因の複合メカニズム**:
  1. **同期パイプラインにおける再描画（`renderApp`）漏れ**:
     - 15秒ごとの定期バックグラウンド同期（`pullDataFromCloud`）の通信中に完了操作が行われた際、レースコンディションを防ぐ `hasPendingPush = true` ガードが作動し、`mergeHabitsDeep` によってデータは最新に合流されていました。
     - しかし、合流直後に **`renderApp()` を呼び出さずに `return;` していた**ため、画面（DOM）が古い実行中のまま放置されていました。
  2. **カードレンダラーにおける優先度判定の逆転**:
     - `cardRenderers.js` において、`isInProgress`（実行中）が `isCompleted`（本日完了済み）よりも先に評価されていました。
     - そのため、本日の目標を達成（`done: true`）していても、同期の隙間でステータスが `in_progress` と判定されると、問答無用で「● 実行中」ピルと「✓ 完了」ボタンが描画されていました。
  3. **対症療法の限界**:
     - 前日（v1.8.7）の修正が「H019（朝食後 キッチンリセット）」専用のハードコードであったため、他のハビットに対する汎用的な防衛になっていませんでした。

### 設計方針とアーキテクチャ
1. **画面描画パイプラインの完全保証（`storageService.js`）**:
   - `pullDataFromCloud` の `hasPendingPush` ガードブロック内において、マージ完了直後に必ず `renderApp()` を呼び出すパイプラインを確立。
   - バックグラウンド通信とユーザー操作がどれほど激しく交錯しても、画面と内部データが 100% 同期するよう保証。
2. **完了ステータス最優先評価＆完全排他化（`cardRenderers.js`）**:
   - カードレンダリング時に `isCompleted` を最優先で評価。
   - `isInProgress` および `isPaused` の判定に `!isCompleted` を厳格に付与。
   - 完了状態にあるハビットには「● 実行中」ピルや「✓ 完了」ボタンが決して描画されず、確実に「✓ 完了」ピルと「↩ 戻す」ボタンが表示されるよう完全排他化。
3. **Zero-Rollback 完了自動整流化防壁（`mergeHabitsDeep`）**:
   - 同期マージ時、ローカルまたはクラウドのどちらか一方でも `completed` であれば完了を優先。
   - 日付別履歴（`history`）のマージ直後、当日の履歴において `done: true` が存在する場合、`status: 'completed'`、`startTimestamp: null`、`accumulatedSeconds = 0` へ自動正規化。
4. **全ハビット健全化マイグレーション（`migrateHabit`）**:
   - H019 ハードコードを全ハビット共通の健全化ロジックへ昇華。当日の履歴で完了しているハビットは、ロード時およびマージ時に自動で `status: 'completed'` かつタイマースタンプをクリア。

## 2. 💡 「知ると面白い、今回の技術の仕組み」解説（エンジニア視点・ユーザー視点）

### エンジニア視点: 「データ層の整合性」と「プレゼンテーション層の整合性」のデカップリング問題
分散システムやリアルタイム同期間のレースコンディションにおいて最も発見が難しいのが、「データベースやクラウドには最新データが正しく書き込まれているのに、ユーザーインターフェース（画面）の描画更新イベントが特定の非同期分岐でスキップされ、見かけ上バグが再発したように見える」という現象です。

今回のインシデントでは：
1. ユーザーが「✓ 完了」をクリック ➔ `saveHabits()` ➔ `renderApp()` が呼ばれ、一瞬画面からカードが消える。
2. しかしその数百ミリ秒前、15秒間隔のサイレント・ハートビート（`pullDataFromCloud`）がクラウドにリクエストを送っていた。
3. サーバーからレスポンスが返ってきたとき、クライアントは「通信中にローカルで変更があった」と検知（`hasPendingPush = true`）。
4. 受信した古いデータと最新のローカルデータを `mergeHabitsDeep` で賢くマージして `localStorage` に保存した。
5. **だが、ここで「プッシュ処理にフォワードするから、この関数はここで終わろう（`return;`）」としてしまい、画面の再描画（`renderApp()`）を呼ばなかった。**
6. その結果、直前の一瞬の描画状態や古いDOMが画面に残ってしまい、ユーザーの目には「完了ボタンを押したのに消えない！」と映ってしまっていたのです。

Gendrive v1.8.8 では、この「非同期ガードブロックにおけるプレゼンテーション層の更新漏れ」を完全に塞ぎ、どのような非同期の隙間であっても、データマージ直後に決定論的に画面を再描画するパイプラインを確立しました。

### ユーザー視点: 「完了したはずなのに消えない」ストレスの完全撲滅
「ハビットの完了ボタンを押したのに、カードが『実行中』のまま画面に残っている…あれ？完了できてないのかな？」と思い、何度も完了ボタンを連打してしまう――これは日々の習慣記録において非常に強いストレスとなります。

今回の v1.8.8 アップデートにより：
- **完了ボタンを押した瞬間、カードは確実に視界から気持ちよく消去され、完了済みとして記録されます。**
- 15秒ごとのクラウド同期が裏でどのようなタイミングで走っていようと、完了したハビットが「実行中」に化けて画面に復活することは二度とありません。
- もしフィルターを「すべて」に切り替えて確認したとしても、カードは美しいグリーンの「✓ 完了」バッジと「↩ 戻す」ボタンで整然と表示され、「● 実行中」や「✓ 完了」ボタンが決して誤表示されない安心設計となりました。

## 3. 🌟 Gendrive v1.8.8 の主要機能・変更点（全機能一覧）

1. **同期通信時の画面再描画パイプライン完全保証 (Sync Render Pipeline Assurance)**:
   - `js/services/storageService.js` の `pullDataFromCloud` において、`hasPendingPush` ガード作動時にも確実に `renderApp()` を呼び出すよう修正。
   - バックグラウンドハートビート通信中の完了操作後、画面描画が古いまま放置される不具合を完全根絶。
2. **カードレンダラーにおける完了ステータス最優先評価 (Render Priority Inversion Fix)**:
   - `js/components/cardRenderers.js` の `renderHabitCardHtml` において、`isCompleted`（本日目標達成済み）を `isInProgress` より最優先で評価。
   - `isInProgress` および `isPaused` の判定に `!isCompleted` 条件を厳格に付与。
   - 完了しているハビットに対して「● 実行中」ピルや「✓ 完了」ボタンが表示される余地をゼロ化。
3. **ハビットディープマージの Zero-Rollback 完了自動整流化 (Zero-Rollback Normalizer)**:
   - `mergeHabitsDeep` において、クラウド・ローカルのどちらか一方でも `completed` であれば完了を優先。
   - 日付別履歴マージ直後、当日分の `history[todayKey].done === true` を検知した場合、自動的に `status: 'completed'`、`startTimestamp = null`、`accumulatedSeconds = 0` へ整流化。
4. **全ハビット健全化マイグレーション (Universal Habit Health Migration)**:
   - 前バージョン（v1.8.7）の特定ハビット（H019）個別コードを全ハビット共通の自動健全化ロジックへと昇華。
   - 当日の履歴で完了しているハビットは、起動ロード時および同期マージ時に自動で `status: 'completed'` かつタイマースタンプをクリア。
5. **Optimistic Direct DOM Mutation Guard (即時DOM完了消去ガード)**:
   - `completeHabit` 実行時、全体再描画や通信待機を挟まずに対象カード要素をその場で即座にフェードアウト消去。通信ラグや再描画タイミングに1ミリ秒も左右されず、クリックした瞬間に確実に画面から消去。
6. **Day-Rollover Auto-Sanitizer (翌朝自動ウェイクアップ・サニタイザー)**:
   - スリープ復帰時（`focus` / `visibilitychange`）および1分ごとの定期監視において、日付変更（`lastProcessedDate !== getTodayKey()`）を自動検知。夜間にPCをスリープさせてブラウザを開いたまま翌朝を迎えた場合でも、朝PCを開いた瞬間にゼロタッチで自動サニタイズ（`sanitizeDailyState()`）と再描画（`renderApp()`）を発火させ、前日のステータス引きずり・翌朝再発を物理的に完全防止。
7. **全スクリプトタグのキャッシュバスター完全適用 (`?v=1.8.8`)**:
   - `index.html` の全 JavaScript スクリプトタグに `?v=1.8.8` を付与し、ブラウザキャッシュによる古いコードの実行を完全根絶。
8. **テストスイートの Daily Isolation 対応と全件 PASS 実証**:
   - `tests/test_habit_deep_merge_and_sync_lifecycle.html` を Daily Isolation（翌日未完了リセット）の仕様に合致した動的日付判定へ改善し、Edge Headless 環境下で全9テストが 100% PASS。
   - 実機 DOM 統合検証テストにおいて、`startHabit('H043')` から `completeHabit('H043')` のライフサイクル全体で「● 実行中」カードが確実に消去され未完了リストから正常除外されることを実証。
